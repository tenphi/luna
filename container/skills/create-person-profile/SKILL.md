# Person profiles

Use this workflow when asked to maintain a person's profile. If durable memory is unavailable, explain that limitation; do not pretend to save a profile or choose a substitute private-data store.

Recall the person and aliases, then read the existing canonical profile before editing. Reuse the established page and knowledge-base taxonomy. Preserve unrelated content, frontmatter, dates, and qualifications; avoid duplicate profiles or a new personal namespace invented for the task.

When the user requests public research, use relevant official biographies, institutional pages, professional publications, or other authoritative sources. Open the pages before relying on claims. A matching name alone is insufficient to establish identity: use the supplied professional context, and leave uncertain matches unmerged. Do not infer sensitive traits or investigate unrelated private contact details, residential information, or data-broker records.

Separate what the user supplied from what the public sources establish. Attribute relationships and preferences to their source rather than describing them as independently verified. Keep URLs and dates beside time-sensitive professional claims. Prefer a concise readable profile to a speculative collection of attributes.

Write only supported changes. Follow the memory service's placement and conflict results; a held or partial write is not a completed save. Check the receipt and read back the stored profile before confirming success. Tell the user what changed, which evidence was limited, and which facts came from their own context.
